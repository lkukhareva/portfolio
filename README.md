# Portfolio

Lizaveta Kukharava's portfolio: one scrolling page generated by Astro, plus a
separate Impressum. No client-side application framework, backend, or production
Node server is needed. Home, About, and Work are sections of `index.html`.
`about.html` and `work.html` remain so older links jump to `/#about` and
`/#work`. Animation work is intentionally separate.

## View locally

Install **Node.js 22.23.4+** and **npm 9.6.5+**, then run from this folder:

```sh
npm ci           # first time, or after dependencies change
npm run dev
```

Open **http://127.0.0.1:3000**. Saved Astro/HTML/CSS changes update the browser
automatically. Stop the server with **Ctrl+C**.

If port 3000 is busy: `npm run dev -- --port 3001`.
Development and production preview bind to loopback and reject port conflicts.

## Edit and check

- Scrolling page: `src/pages/index.astro` and `src/components/{Home,About,Work}Section.astro`.
- Compatibility jumps: `src/pages/{about,work}.astro`. Legal page: `src/pages/impressum.astro`.
- Shared document and metadata: `src/layouts/BaseLayout.astro`.
- Shared navigation, footer, and work cards: `src/components/`.
- Project copy, links, and image references: `src/data/projects.ts`.
- Shared styling: `public/style.css`. Section layouts: `public/css/`. Scroll state: `public/scroll-nav.js`.
- Original media: `public/`, including `assets/` and `helvetica_font/`.
- Astro configuration: `astro.config.mjs`; agent guidance: `AGENTS.md`.

CSS and images remain unprocessed in `public/` to preserve the current rendering
and public URLs. Image optimization and CSS restructuring can be adopted during
the redesign; they are not required for this migration.

```sh
npm run check    # Astro/TypeScript diagnostics
npm test         # fresh static build, then all regression and HTTP checks
```

Tests exercise the generated HTML, the scroll-navigation script, and both local
servers. They protect copy, links, metadata, accessibility structure, published
files, 404s, and port-conflict behavior. Intentional redesign changes require
updating the relevant expectations, not weakening unrelated checks.

## Build and deploy

```sh
npm run build
npm run preview # http://127.0.0.1:3000; -- --port 3001 overrides the port
```

Publish **only `dist/`** to a static host after building. Do not publish the
repository root or run the development/preview server in production. The output
contains `index.html`, `about.html`, `work.html`, and `impressum.html`, with the
original asset paths. `about.html` and `work.html` are jump documents, not
separate layouts. Keep normal static-file routing and 404 handling; no SPA
fallback or server adapter is required. Configure your hosting provider's build
command as `npm run build` and its publish directory as `dist`.

`npm run preview` checks the build locally; it is not a production server.

### GitHub Pages

`.github/workflows/deploy.yml` validates, builds, and deploys `dist/` on pushes to
`master`, or through **Actions → Deploy → Run workflow** on `master`. It follows a
single-job deployment flow, uses Node.js 24 with npm, pins actions to commit SHAs,
and cancels superseded runs. No personal access token or additional secret is
required.

One-time repository/domain setup:

1. In **Settings → Pages → Build and deployment**, set **Source** to
   **GitHub Actions**.
2. In **Settings → Pages → Custom domain**, enter **`lizavetakuk.com`**. Configure
   the domain's DNS for GitHub Pages and enable **Enforce HTTPS** once available.
   See [GitHub's custom-domain guide](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site).
3. Ensure the `github-pages` environment permits deployments from `master`.

The workflow reads the origin and base path from GitHub Pages, so the configured
custom domain builds at `/`. If no custom domain is configured, it also supports
the repository URL at `https://lkukhareva.github.io/portfolio/`. Local development
is unchanged. The workflow does not configure DNS or change repository settings.

Optional HTML validation after building:

```sh
npx --yes html-validate@11.17.0 --preset standard,a11y dist/index.html dist/about.html dist/work.html dist/impressum.html
```
